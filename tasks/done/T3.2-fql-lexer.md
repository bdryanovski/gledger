# T3.2 — FQL Lexer (Tokenizer)

## Goal
Build the FQL (Financial Query Language) tokenizer that converts a FQL query string
into a stream of tokens for the FQL parser. Fix the known bugs from the examples
(negative numbers, COUNT(*) without alias).

## Context
FQL is a SQL-like query language. Its lexer is simpler than the journal lexer because
FQL is a single-line expression language with well-defined keywords. The lexer must
correctly handle: keywords, identifiers, string literals, numeric literals (including
negative numbers), operators, and special characters.

**Depends on:** T3.1 (SQLite backend exists so we know what FQL will query)
**Blocks:** T3.3 (FQL parser)

## Create `fql/lexer.go`

### Token types

```go
package fql

type TokenType int

const (
    // Literals
    FQL_NUMBER  TokenType = iota // integer or float, including negative
    FQL_STRING                   // 'single-quoted string'
    FQL_IDENT                    // identifier (table name, column name, alias)
    FQL_STAR                     // * (for SELECT *, COUNT(*))

    // Keywords (case-insensitive)
    FQL_SELECT
    FQL_DISTINCT
    FQL_FROM
    FQL_WHERE
    FQL_AND
    FQL_OR
    FQL_NOT
    FQL_IN
    FQL_LIKE
    FQL_BETWEEN
    FQL_IS
    FQL_NULL
    FQL_GROUP
    FQL_BY
    FQL_HAVING
    FQL_ORDER
    FQL_ASC
    FQL_DESC
    FQL_LIMIT
    FQL_OFFSET
    FQL_AS

    // Aggregate functions
    FQL_COUNT
    FQL_SUM
    FQL_AVG
    FQL_MIN
    FQL_MAX

    // Operators
    FQL_EQ      // =
    FQL_NEQ     // != or <>
    FQL_LT      // <
    FQL_LTE     // <=
    FQL_GT      // >
    FQL_GTE     // >=

    // Punctuation
    FQL_COMMA   // ,
    FQL_LPAREN  // (
    FQL_RPAREN  // )
    FQL_DOT     // .

    // Special
    FQL_EOF
    FQL_ERROR
)

type Token struct {
    Type    TokenType
    Literal string  // raw text of the token
    Pos     int     // character position in the input
}
```

### Lexer struct

```go
type Lexer struct {
    input  string
    pos    int
    tokens []Token // cached tokens (fully tokenize upfront)
    index  int     // current position in tokens slice
}

func NewLexer(input string) *Lexer

// Tokenize tokenizes the entire input and stores in l.tokens.
// Returns error if an unexpected character is found.
func (l *Lexer) Tokenize() error

// Next returns the next token (advances position).
func (l *Lexer) Next() Token

// Peek returns the next token without advancing.
func (l *Lexer) Peek() Token

// PeekAt returns the token N positions ahead without advancing.
func (l *Lexer) PeekAt(n int) Token
```

### Key tokenization rules

#### Negative numbers — the critical fix
The bug in the examples: `amount < -100` errors with "Unexpected character '-'".

**Fix:** When the lexer encounters `-`:
- If the previous meaningful token was an operator (`<`, `>`, `=`, etc.), a keyword
  (`IN`, `BETWEEN`, `HAVING`, `WHERE`), or a comma or open paren → treat `-` as a
  unary minus and include it in the next number token: `FQL_NUMBER("-100")`
- Otherwise → treat `-` as an operator token `FQL_MINUS`

Since we fully tokenize upfront, we can use lookahead + context:
```go
case '-':
    if isUnaryContext(l.tokens) {
        // scan the number including the minus sign
        l.scanNumber(true) // true = include leading minus
    } else {
        l.tokens = append(l.tokens, Token{Type: FQL_MINUS, Literal: "-", Pos: l.pos})
        l.pos++
    }
```

```go
func isUnaryContext(tokens []Token) bool {
    if len(tokens) == 0 {
        return true
    }
    last := tokens[len(tokens)-1].Type
    return last == FQL_EQ || last == FQL_NEQ || last == FQL_LT || last == FQL_LTE ||
        last == FQL_GT || last == FQL_GTE || last == FQL_COMMA || last == FQL_LPAREN ||
        last == FQL_AND || last == FQL_OR || last == FQL_NOT ||
        last == FQL_BETWEEN || last == FQL_IN || last == FQL_HAVING || last == FQL_WHERE
}
```

#### String literals
Single-quoted strings: `'value'`. Scan until matching `'`. Allow `''` as escaped quote.
Produce `FQL_STRING` with the content (without quotes) as literal.

#### Identifiers
Start with a letter or `_`, followed by letters, digits, `_`. Look up in keywords map
(case-insensitive). If found → return keyword token. Else → `FQL_IDENT`.

#### Numbers
Digits, optional decimal point and more digits. No exponent for simplicity.

#### Star `*`
A bare `*` → `FQL_STAR`. This handles both `SELECT *` and `COUNT(*)`.

#### Whitespace
Skip all whitespace (spaces, tabs, newlines).

#### Comments — not applicable
FQL queries are single-line; no comment syntax needed.
