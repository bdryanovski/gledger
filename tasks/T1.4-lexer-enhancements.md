# T1.4 — Enhance Lexer

## Goal

Extend the lexer to correctly tokenize multi-currency amounts, transaction status markers,
tag syntax in comments, and fix the comment-handling edge cases.

## Context

The current lexer (`lexer/lexer.go`) only handles `$`-prefixed amounts and has limited
comment support. We need it to handle the full hledger journal format including
multi-currency, tags, and status markers.

**Depends on:** T1.3 (AST types with new TokenTypes)
**Blocks:** T1.5 (parser enhancements)

---

## Changes to `lexer/lexer.go`

### 1. Multi-currency amount tokenization

Currently the lexer handles `$123.45` and `-$123.45` only.

Extend `TOKEN_AMOUNT` tokenization to handle:

- `$123.45` — USD prefix
- `£123.45` — GBP prefix (Unicode rune `\u00A3`)
- `€123.45` — EUR prefix (Unicode rune `\u20AC`)
- `123.45 BGN` — amount followed by 3-letter currency code
- `BGN 123.45` — 3-letter currency code followed by amount
- `-$123.45`, `-£123.45`, etc. — negated prefixed amounts
- `123.45` — bare number (no currency symbol, uses journal default)
- Numbers with comma separators: `1,234.56` (strip commas during tokenization)

**Implementation approach:**
When scanning for a token and we encounter a digit or `-` followed by a digit (or a
currency symbol), enter amount-scanning mode. Look ahead for:

1. Optional sign (`-`)
2. Optional currency prefix symbol (`$`, `£`, `€`)
3. Digits and `.` and `,` (the number)
4. Optional trailing whitespace + 3-letter code

Produce a single `TOKEN_AMOUNT` with the full literal (e.g., `"£123.45"`, `"100 BGN"`).
Let `utils.ParseAmount` handle the interpretation.

### 2. Transaction status marker tokenization

Produce `TOKEN_STATUS` when the character `!` or `*` appears immediately after the date
and a space, at the start of a transaction line.

Example:

```
2025-01-15 * Cleared transaction
2025-01-15 ! Pending transaction
```

After tokenizing the date, if the next non-space character is `!` or `*`, emit
`TOKEN_STATUS` with that character as the literal, then continue to the description.

### 3. Tag syntax in comments

When inside a comment (after `;`), look for `key: value` pairs.

The lexer does not need to deeply parse tags — it can emit the whole comment content
as `TOKEN_COMMENT` with the full literal including the `;` prefix. The parser will
extract tags from comment literals. This keeps the lexer simple.

However, the lexer must ensure comment content is preserved faithfully (no truncation).
Currently verify the lexer captures the full comment text up to the newline.

### 4. Indented posting detection

The current lexer uses `TOKEN_INDENT` for lines starting with 2+ spaces. Verify this
works correctly and doesn't conflict with the new amount parsing.

A posting line looks like:

```
    expenses:groceries    $45.32  ; inline comment
```

The sequence should be:

```
TOKEN_INDENT
TOKEN_ACCOUNT "expenses:groceries"
TOKEN_AMOUNT "$45.32"
TOKEN_COMMENT "; inline comment"
TOKEN_NEWLINE
```

Ensure the lexer correctly transitions from account scanning to amount scanning when
it encounters a currency symbol or digit after whitespace.

### 5. Handle multiple spaces between account and amount

Between the account name and the amount on a posting line, there can be 2+ spaces
(hledger uses alignment). The lexer must treat multiple spaces as a delimiter, not
as significant tokens. Currently verify this works.

### 6. Preserve line/column positions for error reporting

The existing lexer tracks `Line` and `Column` on each token. Ensure the new token
types also have correct position information.

### 7. Edge cases to handle

- Empty lines between transactions (should produce `TOKEN_NEWLINE`, not error)
- Comment-only lines at top level (`;` at column 0)
- Comment at end of posting line (after amount)
- Date with status: `2025-01-15 * Description`
- Amount with no currency symbol: just `45.32` (bare number)

## Testing the Lexer

Since there are no test files yet, add a simple manual test in `lexer/lexer_test.go`:

```go
package lexer

import "testing"

func TestMultiCurrencyAmounts(t *testing.T) {
    inputs := []struct {
        input    string
        wantType TokenType
        wantLit  string
    }{
        {"$45.32", TOKEN_AMOUNT, "$45.32"},
        {"£10.50", TOKEN_AMOUNT, "£10.50"},
        {"€25.00", TOKEN_AMOUNT, "€25.00"},
        {"100 BGN", TOKEN_AMOUNT, "100 BGN"},
        {"-$45.32", TOKEN_AMOUNT, "-$45.32"},
    }
    for _, tc := range inputs {
        l := NewLexer(tc.input)
        tok := l.NextToken()
        if tok.Type != tc.wantType {
            t.Errorf("input %q: got type %v, want %v", tc.input, tok.Type, tc.wantType)
        }
        if tok.Literal != tc.wantLit {
            t.Errorf("input %q: got literal %q, want %q", tc.input, tok.Literal, tc.wantLit)
        }
    }
}

func TestStatusTokens(t *testing.T) {
    input := "2025-01-15 * Cleared\n"
    l := NewLexer(input)
    tokens := []Token{}
    for tok := l.NextToken(); tok.Type != TOKEN_EOF; tok = l.NextToken() {
        tokens = append(tokens, tok)
    }
    // Should have: DATE, STATUS("*"), STRING("Cleared"), NEWLINE
    if len(tokens) < 3 {
        t.Fatalf("expected at least 3 tokens, got %d", len(tokens))
    }
    if tokens[1].Type != TOKEN_STATUS {
        t.Errorf("expected TOKEN_STATUS at index 1, got %v", tokens[1].Type)
    }
}

func TestCommentBetweenTransactions(t *testing.T) {
    input := "2025-01-15 Test\n    a:b  $10\n    c:d  -$10\n\n; comment\n2025-01-16 Test2\n    a:b  $5\n    c:d  -$5\n"
    l := NewLexer(input)
    var tokens []Token
    for tok := l.NextToken(); tok.Type != TOKEN_EOF; tok = l.NextToken() {
        tokens = append(tokens, tok)
    }
    // Should not produce TOKEN_ERROR
    for _, tok := range tokens {
        if tok.Type == TOKEN_ERROR {
            t.Errorf("unexpected TOKEN_ERROR: %q", tok.Literal)
        }
    }
}
```
