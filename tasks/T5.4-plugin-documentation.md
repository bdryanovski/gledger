### 2. Plugin Interface Reference

Document every method in the `Plugin` interface with:

- Signature
- When it is called
- What the return value means
- Example implementation

```go
// Name returns the unique identifier for this plugin.
// Must be unique across all registered plugins.
// Used for: config references, CLI commands, error messages.
// Example: "my-tax-calculator"
Name() string

// Initialize is called once when the plugin is loaded, before any data is processed.
// config: plugin-specific config from ~/.doublebook/config.yaml:
//   plugins:
//     my-plugin:
//       api_key: "..."
//       output_dir: "~/reports"
Initialize(config map[string]interface{}) error

// OnParse is called after the journal files are parsed.
// Use it to validate, enrich, or index the loaded data.
// Returning an error aborts the current operation.
OnParse(transactions []*ast.Transaction) error

// OnAdd is called after a new transaction is added (via 'insert' or 'add').
// The transaction has already been validated and written to the journal.
OnAdd(transaction *ast.Transaction) error

// OnFilter is called when transactions are filtered for a query.
// You can add additional filtering logic here.
// Return the (possibly reduced) slice of transactions.
OnFilter(transactions []*ast.Transaction, filter interpreter.Filter) []*ast.Transaction

// OnReport is called when generating reports.
// Return a string to append to the report output, or "" to add nothing.
OnReport(transactions []*ast.Transaction) string

// OnImport is called after CSV rows are parsed but before they are written.
// Use it to further categorize or tag imported transactions.
OnImport(rows []ImportRow, importMapName string) error

// Shutdown is called when DoubleBook exits cleanly.
// Use it to flush caches, close connections, etc.
Shutdown() error
```

### 3. Quick Start: Writing Your First Plugin

Walk through creating a "Tax Summary" plugin step by step:

```go
package extensions

import (
    "fmt"
    "doublebook/ast"
    "doublebook/interpreter"
    "doublebook/plugin"
)

// TaxSummaryPlugin calculates estimated tax on income.
type TaxSummaryPlugin struct {
    plugin.DefaultPlugin  // provides no-op defaults for all hooks
    TaxRate float64
}

func (p *TaxSummaryPlugin) Name() string    { return "tax-summary" }
func (p *TaxSummaryPlugin) Version() string { return "1.0.0" }
func (p *TaxSummaryPlugin) Description() string {
    return "Calculates estimated tax on income accounts"
}

func (p *TaxSummaryPlugin) Initialize(config map[string]interface{}) error {
    if rate, ok := config["tax_rate"].(float64); ok {
        p.TaxRate = rate
    } else {
        p.TaxRate = 0.20 // default 20%
    }
    return nil
}

func (p *TaxSummaryPlugin) OnReport(transactions []*ast.Transaction) string {
    var totalIncome float64
    for _, txn := range transactions {
        for _, posting := range txn.Postings {
            if strings.HasPrefix(posting.Account, "income:") {
                totalIncome += posting.Amount
            }
        }
    }
    totalIncome = -totalIncome // income is negative in double-entry
    estimatedTax := totalIncome * p.TaxRate

    return fmt.Sprintf(
        "Tax Summary\n  Total Income:    $%.2f\n  Estimated Tax (%d%%): $%.2f\n",
        totalIncome, int(p.TaxRate*100), estimatedTax,
    )
}
```

### 6. Plugin CLI Commands

```
doublebook plugin list              — list all registered plugins
doublebook plugin run <name>        — run a plugin's default command
doublebook plugin run <name> help   — show plugin-specific help
doublebook plugin run sql-export --output ~/finance.db
doublebook plugin run recurring status
doublebook plugin run recurring generate
```

### 7. Using `DefaultPlugin`

Explain why embedding `plugin.DefaultPlugin` is recommended:

- New hooks added in future versions won't break existing plugins
- Only override the hooks you need
- The `DefaultPlugin.OnFilter` returns the unmodified transaction list

### 8. Available AST Types

Document the key types a plugin author will use:

- `ast.Transaction` — all fields
- `ast.Posting` — all fields
- `ast.Amount` — Value, Currency, and helper methods
- `interpreter.Filter` — BeginDate, EndDate, Account, Tags

### 9. Examples of What Plugins Can Do

| Use Case                | Hooks           | Description                                          |
| ----------------------- | --------------- | ---------------------------------------------------- |
| Auto-tagging            | OnImport, OnAdd | Tag transactions based on description patterns       |
| Validation              | OnAdd           | Enforce naming conventions for accounts              |
| Sync to external system | OnAdd           | POST to a budget app API when a transaction is added |
| Custom reports          | OnReport        | Generate PDF reports, dashboards                     |
| Data export             | OnParse         | Export to CSV, SQL, Google Sheets                    |
| Budgets                 | OnReport        | Alert when spending exceeds budget per category      |
| Currency                | OnImport        | Convert all amounts to a single base currency        |

### 10. Limitations and Future Work

- Currently no hot-reload (must restart DoubleBook)
- Go plugin `.so` files are experimental — prefer registering built-in plugins
- Plugins run in the same process; a crashing plugin will crash DoubleBook
- Future: sandboxed plugin execution via WASM or subprocess
