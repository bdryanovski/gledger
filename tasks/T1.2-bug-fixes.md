# T1.2 — Fix Existing Bugs in Current Codebase

## Goal

Fix all identified bugs in the existing code before adding new features. This ensures
we start Phase 1 enhancements on a solid, working foundation.

## Context

The existing codebase has several known bugs discovered during code review. These need
to be fixed before the TUI and CLI are used as a base for new features.

**Depends on:** T1.1 (rename must be done first so import paths are correct)
**Blocks:** T1.7 (interpreter), T1.8 (balance command), TUI work

---

## Bugs to Fix

### Bug 1: TUI table column order reversed (`ui/ui.go`)

**Location:** `updateTableRows` function in `ui/ui.go`

**Problem:** The table columns are defined as `Date | Description | Amount | Account`
but `updateTableRows` assigns `Account` to column index 2 (Amount position) and
`Amount` to column index 3 (Account position).

**Fix:** Swap the values so:

- Column 0 = Date (formatted as string)
- Column 1 = Description
- Column 2 = Amount (formatted with currency)
- Column 3 = Account name

Inspect the existing `columns` slice definition and the `updateTableRows` function,
then correct the index assignments.

### Bug 2: ESC key does nothing in report view (`ui/ui.go`)

**Location:** `updateReport` function in `ui/ui.go`

**Problem:** When the user presses ESC in the report view, `updateReport` returns
`m, nil` without changing the view. There is no way to navigate back to the list.

**Fix:** In the `updateReport` key handler, add:

```go
case "esc", "q":
    m.currentView = VIEW_LIST
    return m, nil
```

### Bug 3: Help text says "FinTrack" (`ui/ui.go`)

**Location:** `viewHelp` function in `ui/ui.go`

**Problem:** The help view contains a leftover string "FinTrack" from a previous rename.

**Fix:** Replace all occurrences of "FinTrack" with "DoubleBook" in the help view output.

### Bug 4: `ParseAmount` hardcodes USD currency (`utils/utils.go`)

**Location:** `ParseAmount` function in `utils/utils.go`

**Problem:** The function strips the `$` sign and hardcodes `Currency: "USD"` regardless
of what currency symbol is present. This will break Phase 1.3 multi-currency work.

**Fix:** Detect the currency from the amount string:

- If starts with `$` → currency = `USD`
- If starts with `£` → currency = `GBP`
- If starts with `€` → currency = `EUR`
- If ends with a 3-letter code like `100 BGN` → currency = `BGN`, value = `100`
- If starts with a 3-letter code like `BGN 100` → currency = `BGN`, value = `100`
- Default (no symbol recognized) → currency = `USD` (preserve old behavior)

Strip the symbol/code before parsing the float. Keep the function signature the same:
`func ParseAmount(s string) ast.Amount`

### Bug 5: Comment tokens break multi-transaction parsing (`parser/parser.go`)

**Location:** `ParseTransactions` main loop in `parser/parser.go`

**Problem:** When a comment appears between transactions (e.g., `; This is a comment`
on its own line), the parser encounters a `TOKEN_COMMENT` where it expects `TOKEN_DATE`
or `TOKEN_EOF`. This either panics or silently breaks parsing of subsequent transactions.

**Fix:** In the main loop of `ParseTransactions`, when the current token is
`TOKEN_COMMENT` or `TOKEN_NEWLINE` and we are at the "expecting a new transaction" state,
skip the token and continue the loop rather than treating it as an error.

Look at how the parser handles the top-level loop and add a skip clause:

```go
// At the top-level loop, skip standalone comments and blank lines
if p.current().Type == lexer.TOKEN_COMMENT || p.current().Type == lexer.TOKEN_NEWLINE {
    p.advance()
    continue
}
```

### Bug 6: `list` CLI command is a stub (`cli/commands/list_command.go`)

**Location:** `RunListCommand` in `cli/commands/list_command.go`

**Problem:** The list command just prints `"Running list command with args: [...]"` and
returns. It does no useful work.

**Fix:** Implement a basic version that:

1. Loads the config
2. Loads the journal file via the interpreter
3. Prints all transactions as a formatted plain-text register (date, description, account, amount)
4. Each posting gets its own line, grouped under the transaction

Format (matches hledger `register` output style):

```
2025-01-15 Grocery Store
    expenses:groceries         $45.32
    assets:checking           -$45.32

2025-01-16 Salary Payment
    assets:checking          $2000.00
    income:salary           -$2000.00
```

This is a temporary implementation — it will be superseded by T1.10 (register command)
but at least makes the command functional.
