# T2.1 — `doublebook insert` Interactive TUI Command

## Goal

Implement `doublebook insert` — a non-fullscreen interactive form using Bubbletea
that collects transaction data with autocomplete and validation, then appends a
properly formatted entry (with a unique ID) to the journal file.

## Context

This is the primary data-entry method for users who don't want to edit the journal file
directly. It should feel fast and smart — autocompleting account names, currencies,
and tags from the existing journal.

**Depends on:** T1.5 (parser), T1.6 (journal writer), T1.7 (interpreter for autocomplete data), T1.8 (context)
**Blocks:** nothing (standalone command)

---

## Architecture

The `insert` command uses Bubbletea but in a non-fullscreen, inline mode — it appears
in the terminal as part of the normal command history, not taking over the screen.

Create `ui/insert.go` for the Bubbletea model, and `cli/commands/insert_command.go`
for the CLI entry point.

## Create `ui/insert.go`

### Model fields

```go
type InsertModel struct {
    // Fields
    fields      []InsertField
    focusIndex  int

    // Autocomplete state
    suggestions []string
    showSuggestions bool
    suggestionIndex int

    // Loaded data for autocomplete
    knownAccounts []string
    knownTags     []string
    knownCurrencies []string

    // State
    done    bool
    aborted bool
    result  *ast.Transaction
    err     error

    // Styling
    styles  InsertStyles
}
```

### Fields in the form

Define these fields in order:

| #   | Field       | Prompt                  | Default                  | Validation                                               |
| --- | ----------- | ----------------------- | ------------------------ | -------------------------------------------------------- |
| 0   | Date        | `Date [YYYY-MM-DD]`     | today                    | Valid date format                                        |
| 1   | Description | `Description`           | (empty)                  | Non-empty                                                |
| 2   | Account 1   | `From/Debit Account`    | (empty)                  | Valid account format (words separated by `:`)            |
| 3   | Amount      | `Amount`                | (empty)                  | Valid number, optionally prefixed/suffixed with currency |
| 4   | Currency    | `Currency`              | USD (or journal default) | 3-letter code or symbol                                  |
| 5   | Account 2   | `To/Credit Account`     | (empty)                  | Valid account format                                     |
| 6   | Tags        | `Tags (key:value, ...)` | (empty)                  | Optional; comma-separated `key:value` pairs              |

### Keyboard navigation

- `Tab` / `Shift+Tab` → move to next/previous field
- `↑` `↓` (or `k` `j`) → scroll through autocomplete suggestions
- `Enter` → confirm autocomplete selection (if suggestions showing) OR move to next field
- `Ctrl+C` or `Escape` → abort, exit without saving
- On the last field, `Enter` or `Tab` → submit the form

### Autocomplete behavior

- **Account fields** (fields 2 and 5): show matching known account names as the user types
  - Filter `knownAccounts` by prefix match of typed text
  - Show at most 8 suggestions below the input
  - If user types `exp`, show `expenses:groceries`, `expenses:rent`, etc.
- **Currency field** (field 4): show common currencies + any found in the journal
- **Tags field** (field 6): show known tag keys as the user types before the `:`

### Autocomplete list rendering

Display suggestions as a numbered list below the current input:

```
From/Debit Account: exp█
  1. expenses:groceries
  2. expenses:rent
  3. expenses:dining
  (↑↓ to select, Enter to confirm)
```

### Validation

On field exit (Tab press), validate:

- Date: try `time.Parse("2006-01-02", value)` — show inline error if invalid
- Description: must be non-empty
- Account 1 & 2: must match `[a-z][a-z0-9]*(:([a-z][a-z0-9]*))*` pattern
- Amount: must parse as a float (after stripping currency symbol)
- If validation fails, keep focus on the field and show error message in red

### Final submission

When all fields are filled and user presses Enter/Tab on the last field:

1. Build a `*ast.Transaction`:
   - Two postings: Account1 with Amount, Account2 with negated Amount
   - Set `Transaction.ID` to a SHA256 hash of `date+description+account1+amount`
   - Set `Transaction.Tags` from parsed tags input
2. Call `transaction.IsBalanced()` — should always be true for this 2-posting form
3. Return the transaction in `result`

### ID generation

```go
import "crypto/sha256"
import "fmt"

func generateID(date, description, account, amount string) string {
    h := sha256.New()
    h.Write([]byte(date + "|" + description + "|" + account + "|" + amount))
    return fmt.Sprintf("%x", h.Sum(nil))[:16]  // first 16 chars of hex
}
```

## Acceptance Criteria

- [ ] `go build ./...` succeeds
- [ ] `./doublebook insert` launches the form inline (not fullscreen)
- [ ] Tab moves between fields
- [ ] Typing `exp` in an account field shows autocomplete suggestions from the journal
- [ ] Pressing `↑`/`↓` navigates the suggestion list
- [ ] Pressing Enter selects a suggestion
- [ ] Invalid date shows an error message and keeps focus on the date field
- [ ] Empty description shows an error
- [ ] Pressing Escape aborts without writing to the journal
- [ ] Successful submission appends a new transaction to the journal
- [ ] The appended transaction includes `; id: <hash>` comment
- [ ] Running `./doublebook balance` after insert shows the new account balance
- [ ] Transaction is properly balanced (postings sum to zero)
