# T2.4 — CLI `import` Command

## Goal
Implement `doublebook import --map FILE.importmap.json data.csv` that uses the
importer pipeline to read a CSV file, deduplicate against the existing journal,
and append new transactions with a clear summary of what was imported.

## Context
Wires together the importmap parser (T2.2) and CSV importer (T2.3) into a
user-facing CLI command.

**Depends on:** T2.2 (importmap), T2.3 (CSV importer), T1.8 (context)
**Blocks:** nothing (standalone command)

---

## Create `cli/commands/import_command.go`

### Command signature
```
doublebook import [flags] <csv-file>

Flags:
  --map FILE     Path to the *.importmap.json file (required)
  --dry-run      Show what would be imported without writing to journal
  --verbose      Show each imported transaction
```

### Implementation

```go
func RunImportCommand(ctx *cli.Context, args []string) error {
    // 1. Parse flags from args: --map, --dry-run, --verbose
    // 2. Validate: --map is required, csv file path must be provided
    // 3. Load the importmap from the --map path
    // 4. Load existing journal to extract known IDs for deduplication
    // 5. Run importer.ImportCSV(csvPath, importmap, existingIDs)
    // 6. If --dry-run: print summary, return without writing
    // 7. If --verbose: print each transaction
    // 8. Append each new transaction to the journal using journal.AppendTransaction
    // 9. Print summary
}
```

### Output format

**Normal run:**
```
Importing from 'exports.csv' using 'my-bank.importmap.json'...

  Processed 152 rows
  Imported:  89 new transactions
  Skipped:   63 duplicates
  Errors:     0 rows failed

Journal updated: ~/.doublebook/data.journal
```

**Dry run (`--dry-run`):**
```
DRY RUN — no changes will be written

Importing from 'exports.csv' using 'my-bank.importmap.json'...

  Processed 152 rows
  Would import:  89 new transactions
  Would skip:    63 duplicates
  Errors:         0 rows failed

(Use without --dry-run to actually import)
```

**Verbose mode (`--verbose`):**
Print each imported transaction after the header, using the same format as `register` output.

**Errors:**
If any rows failed to parse, list them at the end:
```
  Warnings (2 rows failed):
    Row 5: could not parse date "N/A" with format "02/01/2006"
    Row 23: amount column is empty
```

### Error handling
- If `--map` is not provided: print usage and return error
- If CSV file doesn't exist: return clear error
- If importmap file doesn't exist: return clear error
- If the importmap is invalid: print validation errors and return error
- Non-fatal row errors (bad date format, empty amount) are collected and shown
  in the summary rather than aborting the entire import

### Progress indicator
For large CSV files (>1000 rows), print a simple progress line that updates:
```
Processing... 450/1523 rows
```
Use carriage return `\r` to update in place.

## Acceptance Criteria

- [ ] `go build ./...` succeeds
- [ ] `./doublebook import --map sample/sample.importmap.json sample/sample.csv` runs without crash
- [ ] Summary shows total rows, imported count, skipped count
- [ ] `--dry-run` shows the summary without modifying the journal
- [ ] `--verbose` shows each transaction that would be imported
- [ ] Running the import a second time skips all rows (all already in journal)
- [ ] Missing `--map` flag shows a helpful error message
- [ ] Non-fatal row errors are shown in the summary, import continues
