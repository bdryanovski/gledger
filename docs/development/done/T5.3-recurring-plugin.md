# T5.3 — Recurring Payments Plugin

## Goal

Implement the `recurring` plugin that manages scheduled recurring payments
(weekly, monthly, yearly, or custom intervals), generates pending transactions
for overdue entries, and reports on amounts spent and projected future spending.

## Context

Many expenses recur on a regular schedule (rent, subscriptions, insurance).
Tracking these separately and getting projections helps with budgeting.

**Depends on:** T5.1 (plugin interface)
**Blocks:** nothing

### Frequency options

- `"daily"` — every day
- `"weekly"` — every week on `day_of_week` (0=Sunday, 1=Monday, ..., 6=Saturday)
- `"monthly"` — every month on `day_of_month`
- `"yearly"` — every year on `month` and `day_of_month`
- `"custom"` — every `interval_days` days

### Schedule types

```go
type Schedule struct {
    ID            string            `json:"id"`
    Description   string            `json:"description"`
    Amount        float64           `json:"amount"`
    Currency      string            `json:"currency"`
    DebitAccount  string            `json:"debit_account"`
    CreditAccount string            `json:"credit_account"`
    Frequency     string            `json:"frequency"`   // daily|weekly|monthly|yearly|custom

    DayOfWeek     int               `json:"day_of_week"`
    Month         int               `json:"month"`

    EndDate       *string           `json:"end_date"`
    Tags          map[string]string `json:"tags"`
```

### Key functions

#### `NextDates(s *Schedule, from, to time.Time) []time.Time`

Returns all dates this schedule fires between `from` and `to`.

```go
func NextDates(s *Schedule, from, to time.Time) []time.Time
```

Logic for each frequency:

- `monthly`: start from `StartDate`, advance month-by-month, collect dates where `DayOfMonth` matches
- `weekly`: start from `StartDate`, advance week-by-week on `DayOfWeek`
- `yearly`: once per year on `Month`/`DayOfMonth`
- `daily`: every day
- `custom`: every `IntervalDays` days from `StartDate`

#### `GeneratePending(s *Schedule, existingTxns []*ast.Transaction) []*ast.Transaction`

Returns transactions that should have been recorded but aren't in the journal.

Logic:

1. Find all dates the schedule fires from `StartDate` to today
2. For each date, check if there's an existing transaction in `existingTxns` that matches:
   - Same date (or within ±3 days tolerance)
   - Same debit account
   - Same amount (within ±5% tolerance for inflation)
   - Tags contain the schedule ID: `recurring_id: <id>`
3. Return a transaction for each unmatched date

#### `ProjectedSpend(s *Schedule, from, to time.Time) float64`

Returns the projected total spend for the schedule between two dates.
