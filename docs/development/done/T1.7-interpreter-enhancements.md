# T1.7 — Interpreter Enhancements

## Goal

Update the interpreter to use the new `journal` package for file I/O, add account
hierarchy balance calculations, and add filtering support (by date range and account).

## Context

The current interpreter (`interpreter/interpreter.go`) does file loading/saving itself
and has a flat balance calculation. We need to delegate file management to the `journal`
package and add the hierarchy and filter support needed by the CLI commands.

**Depends on:** T1.6 (journal package), T1.5 (parser), T1.3 (AST)
**Blocks:** T1.8, T1.9, T1.10 (all CLI commands)

---

## Changes to `interpreter/interpreter.go`

### 1. Delegate file loading to `journal` package

Replace the current `LoadFromFile` method with one that uses `journal.Load`:

```go
// LoadJournal loads all journal files for the given name.
// Uses the journal package for multi-file support.
func (i *Interpreter) LoadJournal(name string) error
```

Remove the old `LoadFromFile` and `SaveToFile` that do direct file I/O.

Keep `SaveToFile` as a wrapper around `journal.WriteAll` for backward compatibility
with any code that calls it directly.

Add:

```go
// AppendTransaction appends a transaction to the journal (handles splitting).
func (i *Interpreter) AppendTransaction(txn *ast.Transaction) error
```

### 2. Add filter support

```go
// Filter holds optional filtering criteria for queries.
type Filter struct {
    BeginDate   string // "YYYY-MM-DD", empty = no limit
    EndDate     string // "YYYY-MM-DD", empty = no limit
    Account     string // partial match against account name, empty = all
    Description string // partial match against description, empty = all
    Tags        map[string]string // tags that must be present
}

// FilteredTransactions returns transactions matching the filter.
func (i *Interpreter) FilteredTransactions(f Filter) []*ast.Transaction
```

Implementation:

- Date filtering: parse and compare date strings (YYYY-MM-DD sorts lexicographically)
- Account filtering: `strings.Contains(posting.Account, f.Account)`
- Description filtering: `strings.Contains(strings.ToLower(txn.Description), strings.ToLower(f.Description))`
- Tag filtering: all tags in `f.Tags` must be present with matching values

### 3. Account hierarchy balance calculation

The current `CalculateBalances()` returns a flat map. Add a tree version:

```go
// AccountNode represents a node in the account hierarchy tree.
type AccountNode struct {
    Name        string
    FullName    string
    Amount      ast.Amount
    Children    []*AccountNode
}

// CalculateBalancesTree returns account balances organized as a hierarchy.
// For example, "expenses:food:groceries" creates:
//   expenses (total of all expenses)
//     food (total of food and groceries)
//       groceries (leaf amount)
func (i *Interpreter) CalculateBalancesTree(f Filter) map[string]*AccountNode
```

**Implementation approach:**

1. Get filtered transactions
2. For each posting, accumulate amounts into a flat map (account→amount) as before
3. Build the tree:
   - Split account names by `:` to get path components
   - Ensure parent nodes exist (create them if not)
   - Accumulate child amounts into parent totals

The tree is indexed by full account name at each level.

Also keep the existing flat `CalculateBalances()` for backward compatibility.

### 4. Group accounts by type

Add a helper that groups accounts by type (top-level component):

```go
// AccountsByType groups account nodes by their top-level type.
// Returns map of type → sorted list of nodes.
// Types: "assets", "liabilities", "equity", "income", "expenses", "other"
func GroupAccountsByType(nodes map[string]*AccountNode) map[string][]*AccountNode
```

### 5. Income Statement calculation

```go
// IncomeStatement holds revenues and expenses for a period.
type IncomeStatement struct {
    Period     string
    Revenues   map[string]ast.Amount // account → amount
    Expenses   map[string]ast.Amount // account → amount
    NetIncome  ast.Amount
}

// GenerateIncomeStatement calculates revenues vs expenses for a date range.
func (i *Interpreter) GenerateIncomeStatement(f Filter) *IncomeStatement
```

Logic:

- Revenues = all `income:*` accounts (typically negative in double-entry, negate for display)
- Expenses = all `expenses:*` accounts (positive)
- NetIncome = sum(revenues) - sum(expenses)

### 6. Keep existing `AddTransaction` behavior

The existing `AddTransaction` validates balance and runs plugins. Keep it, but update
it to call `AppendTransaction` instead of doing its own file I/O.

### 7. Update `GenerateBalanceReport` to use tree structure

The existing `GenerateBalanceReport()` string method can be kept but update it to use
`CalculateBalancesTree` for the output — showing proper hierarchy indentation:

