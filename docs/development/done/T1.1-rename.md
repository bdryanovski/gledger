# T1.1 — Rename Project: gledger → doublebook

## Goal

Rename every reference to the old name `gledger` to `doublebook` across the entire codebase —
module path, binary name, package imports, Makefile targets, and user-facing strings.

## Context

The project was prototyped as `gledger`. The final product is `doublebook`. This rename must
happen first because every subsequent task will add new files that import internal packages.
Getting the module name right now avoids a second rename pass later.

**Depends on:** nothing (first task)
**Blocks:** all other tasks

---

## Steps

### 1. Update `go.mod`

- Change `module gledger` → `module doublebook`
- Remove the duplicate YAML dependency `go.yaml.in/yaml/v3 v3.0.4` (keep only `gopkg.in/yaml.v3`)
- File: `go.mod`

### 2. Update all internal import paths

Every Go file that imports an internal package uses paths like `"gledger/ast"`.
Replace all occurrences with `"doublebook/ast"`, `"doublebook/lexer"`, etc.

Files to update (check each one):

- `gledger.go` — imports `gledger/cli`, `gledger/ui`, `gledger/config`
- `cli/cli.go` — imports `gledger/cli/commands`, `gledger/config`, `gledger/interpreter`
- `cli/commands/add_command.go` — imports `gledger/config`, `gledger/interpreter`, `gledger/ast`
- `cli/commands/list_command.go` — imports (check what it imports)
- `ui/ui.go` — imports `gledger/interpreter`, `gledger/ast`, `gledger/config`, `gledger/utils`
- `interpreter/interpreter.go` — imports `gledger/ast`, `gledger/parser`, `gledger/plugin`, `gledger/config`, `gledger/utils`
- `parser/parser.go` — imports `gledger/ast`, `gledger/lexer`
- `plugin/plugin.go` — imports `gledger/ast`
- `plugin/extentions/template_plugin.go` — imports `gledger/ast`, `gledger/plugin`
- `config/config.go` — check imports
- `utils/utils.go` — check imports

**Strategy:** run a global find-and-replace of `"gledger/` → `"doublebook/` in all `.go` files.

### 3. Update `Makefile`

- Change the binary output name from `gledger` (or whatever it currently is) to `doublebook`
- Update any `go build` commands
- Update `.gitignore` to ignore `doublebook` binary instead of `gledger`

### 4. Update user-facing strings

- `cli/cli.go`: change any printed references to "gledger" to "doublebook"
- `ui/ui.go`: fix the leftover "FinTrack" string in the help view — change to "DoubleBook"
- `cli/commands/add_command.go`: update any usage text
- Check `config/config.go` for any default paths like `~/.gledger/` → `~/.doublebook/`

### 5. Update `config/config.go` default paths

- `DataFile` default: `~/.gledger/data.txt` → `~/.doublebook/data.journal`
- Config file path: `~/.gledger/config.yaml` → `~/.doublebook/config.yaml`
- Update the config directory creation logic to use the new path

### 6. Rename example file (optional cosmetic)

- `example/transactions.txt` → `example/transactions.journal`
  (update any references to this filename in code)

### 7. Update `go.sum`

After editing `go.mod`, run:

```bash
go mod tidy
```

This regenerates `go.sum` and removes the unused `go.yaml.in/yaml/v3` entries.

## Acceptance Criteria

- [ ] `go mod tidy` runs without errors
- [ ] `go build ./...` succeeds with zero errors
- [ ] `go build -o doublebook .` produces a working binary named `doublebook`
- [ ] Running `./doublebook` launches the TUI (same as before, just renamed)
- [ ] Running `./doublebook balance` or `./doublebook help` shows "doublebook" in output, not "gledger"
- [ ] No string `gledger` remains in any `.go` file (verify with grep)
- [ ] No string `FinTrack` remains in any `.go` file
- [ ] Config defaults now use `~/.doublebook/` paths
- [ ] `go.mod` has no `go.yaml.in/yaml/v3` entry

```bash

go build ./...

# No old name references

grep -r "FinTrack" --include="*.go" .

# Module check
head -3 go.mod

# Binary works
./doublebook help
```
